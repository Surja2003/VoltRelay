# VoltRelay Command Center

VoltRelay Command Center is a lightweight operations dashboard for monitoring an electric two-wheeler battery-swapping network. It turns operational event data into an executive-friendly view of revenue, contribution margin, demand, station performance, rider activity, customer support, battery health, and data quality.

The dashboard is intentionally self-contained: the browser loads a generated JavaScript data bundle and renders the interface with vanilla HTML, CSS, and JavaScript.

## Highlights

- Executive overview with KPI cards, trends, failure analysis, and city scorecards
- Operations view with demand heatmaps, stockout rates, queue waits, and station rankings
- Rider and fleet-partner performance analysis
- Support ticket volume, unresolved rate, CSAT, resolution time, and contact-channel analysis
- Battery state-of-health, supplier degradation, and replacement-risk analysis
- Dedicated data-quality panel with transparent, non-destructive handling of source issues
- City and date-range filters across analytical views
- Light/dark theme support with system preference detection
- Responsive layout for desktop and smaller screens

## Dashboard sections

| Section | Purpose |
| --- | --- |
| **Executive Overview** | Revenue, contribution margin, swap volume, failure rate, and city-level performance |
| **Operations** | Demand by weekday/hour, battery stockouts, queue waits, failure rates, and station leaderboard |
| **Riders & Partners** | Active riders, segment revenue, and fleet-partner performance |
| **Support** | Ticket trends, unresolved cases, CSAT, resolution time, categories, and channels |
| **Battery Health** | Supplier health, SOH distribution, degradation by pack age, and retirement signals |
| **Data Quality** | Counts and explanations for flagged records and transformation decisions |

## Quick start

No frontend build tool is required.

1. Open a terminal in this directory.
2. Start a local static server:

   ```powershell
   python -m http.server 8000
   ```

3. Open <http://localhost:8000> in a browser.

Opening `index.html` directly may work in some browsers, but a local server is recommended for consistent asset loading and browser security behavior.

## Regenerating the data bundle

`data.js` is generated by [`build_data.py`](./build_data.py). The script reads source CSV files from the parent hackathon directory and writes the compact browser-ready bundle back to this dashboard directory.

Install the Python dependencies:

```powershell
python -m pip install numpy pandas
```

Run the pipeline from the hackathon directory:

```powershell
python dashboard\build_data.py
```

Expected source files in the parent directory:

- `stations.csv`
- `riders.csv`
- `fleet_partners.csv`
- `swap_events.csv`
- `station_hourly_status.csv`
- `support_tickets.csv`
- `batteries.csv`

The swap-event and station-status files are processed in chunks to keep memory usage manageable. The output is written as:

```text
dashboard\data.js
```

## Data handling principles

The pipeline preserves source rows and flags data-quality conditions instead of silently deleting or imputing records. Examples include:

- Correcting the known firmware `v3.2.0` timestamp offset for the affected period
- Separating test stations from business KPIs while retaining them in station-level reporting
- Flagging missing and outlier odometer readings
- Preserving offline-batch events using their event timestamp
- Mapping city-name variants to canonical city labels while retaining the original source values
- Calculating CSAT from rated tickets only
- Calculating stockout rates from observed telemetry hours without treating missing telemetry as zero inventory

## Technical structure

```text
dashboard/
├── index.html       # Dashboard shell, styles, views, and client-side rendering
├── data.js          # Generated window.VR_DATA bundle consumed by the dashboard
├── build_data.py    # CSV aggregation and data-quality preparation pipeline
└── README.md        # Project documentation
```

The frontend uses:

- Vanilla HTML, CSS, and JavaScript
- [Chart.js](https://www.chartjs.org/) loaded from jsDelivr
- Inter and JetBrains Mono fonts loaded from Google Fonts

Because the dashboard currently loads Chart.js and fonts from CDNs, an internet connection is required for the full visual experience unless those assets are vendored locally.

## Metric notes

- **Contribution margin** is shown as revenue minus grid energy cost in the overview.
- **Station margin** additionally accounts for rent and maintenance in the station leaderboard.
- **Failure rate** is based on non-completed swap attempts.
- **Active riders** are distinct riders with at least one completed swap in the selected period.
- **Observed CSAT** excludes tickets without a customer rating.
- **Battery replacement risk** uses the dashboard’s 80% state-of-health threshold.

## Limitations

- This is a static analytical dashboard; it does not persist user changes or provide a backend API.
- Filters and visualizations operate on the generated `data.js` snapshot.
- Source CSV files are not included in this dashboard directory and must be available before running the aggregation script.
- The project does not currently include an automated test suite or frontend package manifest.
